Observability

AgentTrace

Network-layer observability for AI agents. Zero agent code changes.

The design stance Capture is the easy part. The value is the reconstruction — turning raw network traffic back into what each agent actually did. So observe and enforce at the infrastructure boundary, rather than trusting the agent to report on itself.

The problem

  • A security owner becomes accountable for agents they didn't build and can't modify.
  • Every tool asks them to either rewrite the agents to add instrumentation, or ship sensitive traffic to an outside cloud. Often neither is allowed.
  • Permissions describe what an agent could do. They say nothing about what it did.

How it works

  • A forward proxy captures LLM calls, tool invocations, database queries and outbound requests — no SDK, no code changes in the agent.
  • Related calls are grouped into readable trace missions, so a run reads as a story rather than a log dump.
  • A model checker flags prompt injection and data-leakage patterns; a policy engine restricts outbound destinations.
  • Fully on-premises. No external dependencies, no traffic leaving the network. Redaction hooks mask secrets and PII at the boundary.

Evaluation

Prompt Arena

A prompt evaluation platform where your prompt variants are the contestants.

The design stance Teams that measure well are the ones that improve fast. Most prompt changes ship on a vibe check — so the useful thing to build isn't a better prompt, it's the machinery that decides whether a change is real.

The loop

  • Submit a prompt variant. It competes against the current production champion in pairwise, LLM-judged battles.
  • It gets promoted only when bootstrap confidence intervals say it's actually better — not when it wins a few rounds.
  • A drift sentinel re-checks the champion hourly with deterministic checkers, so regressions surface without anyone watching.

Design decisions worth defending

  • Bradley-Terry ratings with bootstrap confidence intervals — a ranking that carries its own uncertainty, instead of a leaderboard that hides it.
  • Position-swapped judging — every pair is judged in both orders, because LLM judges have a position bias and an unswapped result measures that bias as much as the prompt.
  • Deterministic by construction — the entire product runs on a seeded mock provider: generation, judging, evolution, test-set drafting. Same seed, byte-identical demo scene. Real provider keys are optional, not required. Reproducibility was a build requirement, not an afterthought.
  • Explainable rankings — every rating drills down to the individual battles behind it.
